## 异步编程基础

在C#中，异步编程是处理长时间运行的任务（如网络请求、文件I/O操作等）而不会阻塞程序执行的一种方式。

### 单线程异步

单线程异步允许在单个线上执行多个任务，通过非阻塞操作和回调机制避免线程阻塞。当一个操作（如 I/O）处于等待状态时，线程会暂时释放并执行其他任务，待操作完成后再通过回调继续处理结果。

#### 特点

- 不创建额外线程：所有任务在同一个线程上交替执行，减少线程切换开销。
- 非阻塞执行：等待 I/O 时线程不会被阻塞，可继续执行其他代码。
- 适用于 I/O 密集型操作：如网络请求、文件读写、数据库查询等。

#### 实现方式

主要通过 **`async/await` 关键字** 和 **`Task` 类** 实现，结合线程池（如 UI 线程或[ASP.NET](https://asp.net/)请求线程）：

#### 实例

- `Unity`协程
- `UniTask`

### 多线程异步

多线程异步通过创建多个线程并行执行任务，利用多核 CPU 同时处理多个操作。每个任务独立运行在不同线程上，适合需要真正并行计算的场景。

#### 特点

- 创建额外线程：通过线程池或手动创建线程，增加 CPU 利用率。
- 真正的并行执行：多个任务同时运行，适合 CPU 密集型操作。
- 线程安全问题：需要处理共享资源的同步（如锁、原子操作）。

#### 实现方式

主要通过 **`Task.Run()`** 或 **`ThreadPool`** 将任务调度到后台线程：

很多人认为异步就是多线程的，但是多线程只是实现异步的其中一种方式，除此之外还有系统中断，定时器，甚至可以自己写一个状态机实现异步（C# 的异步实现类似状态机）。

### 关键字

#### async

- 作用：修饰方法，将方法声明为异步方法。
- 特点：
  - 其返回值必须是`void/Task/Task<T>`其中一个。
  - 方法内的语句至少包含一个`await`关键字，否则会被同步的方式执行。
  - 不会阻塞调用线程，立即返回未完成的`Task`。

#### await

- 作用：暂停异步方法执行，等待 `Task` 完成，同时不会阻塞调用线程。
- 特点：
  - 只能出现在`async`方法中。
  - 可用于任何实现了 `GetAwaiter()` 方法的类型（如 `Task`、`ValueTask`）。
  - 当 `Task` 完成后，恢复方法执行并返回结果（若有）。

#### Task

- 作用：作为异步函数的返回值
- 常见类型：`Task`、`Task<T>`、`ValueTask`、`ValueTask<T>`。

#### 示例代码

```c#
public class Test
{
    public async void Run()
    {
        TestAsync();
        
        await TestAsync1();
        
        Task<int> task2 = TestAsync2();
        await task2;
        int result2 = await TestAsync2();
    }

    private async void TestAsync()
    {
        await Task.Delay(1000); 
    }

    private Task TestAsync1()
    {
        return Task.Delay(1000);
    }
    
    private async Task<int> TestAsync2()
    {
        await Task.Delay(1000);
        return 100;
    }
}
```

#### 取消任务

在 C# 中，`CancellationTokenSource` 是用于协作式取消异步操作的核心类型。通过它可以向一个或多个任务发送取消信号，任务在接收到信号后可选择优雅地终止执行。

```c#
using System;
using System.Threading;
using System.Threading.Tasks;

public class Test
{
    public async Task RunAsync()
    {
        // 创建 CancellationTokenSource 实例
        using var cts = new CancellationTokenSource();
        // 启动可取消的任务
        Task operation = LongRunningOperationAsync(cts.Token);
        // 模拟一段时间后取消任务
        await Task.Delay(2000);
        cts.Cancel(); // 发送取消信号
        try
        {
            await operation; // 等待任务完成（可能已被取消）
        }
        catch (OperationCanceledException)
        {
            Console.WriteLine("任务已被取消");
        }
    }
    // 支持取消的异步方法
    private async Task LongRunningOperationAsync(CancellationToken token)
    {
        while (!token.IsCancellationRequested)
        {
            Console.WriteLine("任务正在执行...");
            await Task.Delay(500, token); // 传递 token 到延时操作
        }
        // 抛出异常以表明任务被取消 方法会在取消请求时抛出 OperationCanceledException。
        token.ThrowIfCancellationRequested();
    }
}
```

## TaskCompletionSource<T>

`TaskCompletionSource<T>`是 C# 中用于手动控制 `Task` 完成状态的强大工具。它允许你将任意操作（同步或异步）包装为可等待的 `Task`，并在操作完成时显式设置结果、异常或取消状态。

- 作用：
  - 解耦任务创建与完成：当无法直接返回 `Task` 时（如回调驱动的 API），可用 `TaskCompletionSource` 桥接传统异步模式（如事件、回调）和 TPL（Task Parallel Library）。
  - 手动控制任务生命周期：通过 `SetResult`、`SetException`、`SetCanceled` 显式设置任务状态。
- 关键方法：
  - `SetResult(T result)`：任务成功完成并设置返回值。
  - `SetException(Exception ex)`： 标记任务失败。
  - `SetCanceled()` ：标记任务被取消并抛出异常 `OperationCanceledException`
  - `TrySetResult(T result)`：尝试任务成功完成并设置返回值，返回值为`bool`值表示任务是否已经完成。
  - `TrySetCanceled()` ：尝试标记任务被取消并抛出异常 `OperationCanceledException，返回值为`bool`值表示任务是否已经完成。
  - `TrySetException(Exception ex)`： 尝试标记任务失败，返回值为`bool`值表示任务是否已经完成。

### 将回调包装为`Task`

将基于回调的异步操作转换为 `Task`：

```c#
public class Test 
{
    //传统加载AssetBundle
    public void LoadAssetBundle(string filePath,Action<AssetBundle> callback)
    {
        AssetBundleCreateRequest assetBundleCreateRequest = AssetBundle.LoadFromFileAsync(filePath);
        assetBundleCreateRequest.completed += (request) =>
        {
            AssetBundle bundle = assetBundleCreateRequest.assetBundle;
            callback?.Invoke(bundle);
        };
    }
    
    //异步编程加载AssetBundle
    public Task<AssetBundle> LoadAssetBundle(string filePath)
    {
        AssetBundleCreateRequest assetBundle = AssetBundle.LoadFromFileAsync(filePath);
        TaskCompletionSource<AssetBundle> taskCompletionSource = new TaskCompletionSource<AssetBundle>();
        assetBundle.completed += operation =>
        {
            taskCompletionSource.SetResult(assetBundle.assetBundle);
        };
        return taskCompletionSource.Task;
    }
}
```

### 将协程包装为`Task`

```c#
using System;
using System.Collections;
using System.Collections.Generic;
using System.Threading;
using System.Threading.Tasks;
using UnityEngine;

public class Test : MonoBehaviour
{
    private async void Start()
    {
        try
        {
            // 普通协程转 Task
            await LongOperation().AsTask(this);
            Debug.Log("Long operation completed!");
            
            // 带返回值的协程
            int result = await GetResult().AsTask<int>(this);
            Debug.Log($"Result: {result}");
            
            // 带取消的协程
            var cts = new CancellationTokenSource(2000); // 2秒后自动取消
            await CancelableOperation().AsTask(this, cts.Token);
        }
        catch (OperationCanceledException)
        {
            Debug.Log("Operation was canceled");
        }
        catch (Exception ex)
        {
            Debug.LogError($"Error: {ex.Message}");
        }
    }
    
    // 普通协程
    private IEnumerator LongOperation()
    {
        yield return new WaitForSeconds(1f);
    }
    
    // 带返回值的协程
    private IEnumerator GetResult()
    {
        yield return new WaitForSeconds(0.5f);
        yield return 42;
    }
    
    // 可取消的协程
    private IEnumerator CancelableOperation()
    {
        while (true)
        {
            Debug.Log("Working...");
            yield return new WaitForSeconds(0.5f);
        }
    }
}

public static class CoroutineExtensions
{
    // 将协程转换为 Task
    public static Task AsTask(this IEnumerator coroutine, MonoBehaviour owner)
    {
        var tcs = new TaskCompletionSource<object>();
        
        // 启动协程并监听完成状态
        owner.StartCoroutine(WrapCoroutine(coroutine, tcs));
        return tcs.Task;
    }
    
    // 带返回值的协程转换
    public static Task<T> AsTask<T>(this IEnumerator coroutine, MonoBehaviour owner)
    {
        var tcs = new TaskCompletionSource<T>();
        
        owner.StartCoroutine(WrapCoroutineWithResult(coroutine, tcs));
        return tcs.Task;
    }
    
    // 监听协程完成，设置 Task 结果
    private static IEnumerator WrapCoroutine(IEnumerator coroutine, TaskCompletionSource<object> tcs)
    {
        yield return coroutine;
        
        try
        {
            // 检查协程是否有返回值（通过 yield return）
            if (coroutine is IEnumerator<object> genericCoroutine)
            {
                tcs.SetResult(genericCoroutine.Current);
            }
            else
            {
                tcs.SetResult(null);
            }
        }
        catch (Exception ex)
        {
            tcs.SetException(ex);
        }
    }
    
    // 处理带返回值的协程
    private static IEnumerator WrapCoroutineWithResult<T>(IEnumerator coroutine, TaskCompletionSource<T> tcs)
    {
        yield return coroutine;
        
        try
        {
            // 尝试获取协程的返回值
            if (coroutine.Current is T result)
            {
                tcs.SetResult(result);
            }
            else
            {
                tcs.SetException(new InvalidOperationException($"Coroutine did not return a value of type {typeof(T)}"));
            }
        }
        catch (Exception ex)
        {
            tcs.SetException(ex);
        }
    }
    
    public static Task AsTask(this IEnumerator coroutine, MonoBehaviour owner, CancellationToken cancellationToken)
    {
        var tcs = new TaskCompletionSource<object>();

        // 注册取消回调
        if (cancellationToken.CanBeCanceled)
        {
            cancellationToken.Register(() =>
            {
                tcs.TrySetCanceled();
            });
        }

        owner.StartCoroutine(WrapCoroutineWithCancellation(coroutine, tcs, cancellationToken));
        return tcs.Task;
    }

    private static IEnumerator WrapCoroutineWithCancellation(IEnumerator coroutine, TaskCompletionSource<object> tcs, CancellationToken cancellationToken)
    {
        while (true)
        {
            // 检查是否取消
            if (cancellationToken.IsCancellationRequested)
            {
                tcs.TrySetCanceled();
                yield break;
            }

            // 推进协程
            bool moveNext;
            try
            {
                moveNext = coroutine.MoveNext();
            }
            catch (Exception ex)
            {
                tcs.TrySetException(ex);
                yield break;
            }

            if (!moveNext)
            {
                // 协程完成
                try
                {
                    tcs.TrySetResult(coroutine.Current);
                }
                catch (Exception ex)
                {
                    tcs.TrySetException(ex);
                }
                yield break;
            }

            // 等待下一帧或嵌套的 yield
            yield return coroutine.Current;
        }
    }
}
```

### 实现超时逻辑

```c#
public class Test 
{
    public async Task<T> WithTimeout<T>(Task<T> task, TimeSpan timeout)
    {
        var tcs = new TaskCompletionSource<T>();

        // 超时逻辑
        var timer = new System.Timers.Timer(timeout.TotalMilliseconds) { AutoReset = false };
        timer.Elapsed += (sender, args) => tcs.TrySetCanceled();
        timer.Start();

        // 等待原任务或超时
        var completedTask = await Task.WhenAny(task, tcs.Task);

        // 清理资源
        timer.Dispose();

        return await completedTask; // 返回结果或抛出异常
    }
}
```

### 实现异步锁

```c#
public class AsyncLock
{
    private TaskCompletionSource<bool>? _tcs = new(true);

    public Task<IDisposable> LockAsync()
    {
        // 等待上一个锁释放
        var currentTask = _tcs.Task;
        
        // 创建新的 TCS 用于下一个请求
        var newTcs = new TaskCompletionSource<bool>();
        Interlocked.CompareExchange(ref _tcs, newTcs, currentTask.AsyncState as TaskCompletionSource<bool>);
        
        // 当 currentTask 完成时，返回锁
        return currentTask.ContinueWith(
            _ => (IDisposable)new Releaser(this),
            CancellationToken.None,
            TaskContinuationOptions.ExecuteSynchronously,
            TaskScheduler.Default);
    }

    private sealed class Releaser : IDisposable
    {
        private readonly AsyncLock _asyncLock;
        public Releaser(AsyncLock asyncLock) => _asyncLock = asyncLock;
        public void Dispose() => _asyncLock._tcs.TrySetResult(true);
    }
}
```

### 使用注意事项

- 状态唯一性：`TaskCompletionSource` 的状态只能设置一次。多次调用 `SetResult`/`SetException`/`SetCanceled` 会抛出异常，建议使用 `TrySet...` 方法。
- 避免内存泄漏：确保在所有可能的路径下都设置了任务状态，否则等待该 `Task` 的代码可能永远不会继续执行。
- 线程安全：`SetResult` 等方法可从任意线程调用，但需注意多线程竞争问题。

### 总结

`TaskCompletionSource` 是连接传统异步模式与现代 `async/await` 范式的桥梁，常用于：

- 封装基于回调的 API。
- 实现自定义异步模式（如异步锁、超时控制）。
- 手动控制复杂任务的完成逻辑。

合理使用 `TaskCompletionSource` 可提升代码的可读性和可维护性，但需严格遵循状态唯一性原则，避免潜在的竞态条件和内存泄漏问题。

## 自定义异步等待器

在 C# 中，自定义异步等待器是实现`async/await`模式扩展的强大方式。通过创建自定义等待器，你可以让任何类型支持 await 操作，从而实现独特的异步行为。

### 核心原理

`async/await`语法糖背后依赖于**可等待模式（Awaitable Pattern）**，而非特定类型。一个类型要成为 “可等待” 的，必须满足以下条件：

- 继承自`INotifyCompletion(或ICriticalNotifyCompletion)`并实现接口
- `bool IsCompleted { get; }`：指示异步操作是否已完成。
- `void OnCompleted(Action continuation)`：注册操作完成时的回调。
- `T GetResult()`：获取异步操作的结果（`void`对应`UniTaskVoid`）。
- `GetAwaiter()`：实现该方法。返回一个实现了`INotifyCompletion`接口的等待器（Awaiter）。

```c#
public class Test : MonoBehaviour
{   
    async void Start()
    {
        await TestCustomAwaiter();
    }
    
    public async Task TestCustomAwaiter()
    {
        Debug.Log("开始");
    
        // 直接await整数（通过扩展方法）
        await 2000.Delay();
    
        Debug.Log("2秒后执行");
    
        // 也可以直接使用DelayAwaitable
        await new DelayAwaitable(1000);
    
        Debug.Log("又过了1秒");
    }
}

// 自定义可等待类型
public class DelayAwaitable
{
    private readonly int _milliseconds;

    public DelayAwaitable(int milliseconds)
    {
        _milliseconds = milliseconds;
    }

    // 返回等待器
    public DelayAwaiter GetAwaiter() => new DelayAwaiter(_milliseconds);
}

// 自定义等待器
public class DelayAwaiter : INotifyCompletion
{
    private readonly int _milliseconds;
    private Action _continuation;

    public DelayAwaiter(int milliseconds)
    {
        _milliseconds = milliseconds;
        IsCompleted = false;
    }

    // 是否已完成
    public bool IsCompleted { get; private set; }

    // 获取结果（这里返回void）
    public void GetResult() { }

    // 注册完成回调
    public void OnCompleted(Action continuation)
    {
        _continuation = continuation;
        
        // 使用Timer模拟延迟
        System.Threading.Timer timer = null;
        timer = new System.Threading.Timer(_ =>
        {
            IsCompleted = true;
            timer.Dispose();
            _continuation?.Invoke();
        }, null, _milliseconds, System.Threading.Timeout.Infinite);
    }
}

// 扩展方法，让int支持await
public static class IntExtension
{
    public static DelayAwaitable Delay(this int milliseconds)
    {
        return new DelayAwaitable(milliseconds);
    }
}
```

### 注意事项

- 线程安全：确保等待器的状态管理是线程安全的。
- 内存管理：避免在等待器中持有大型对象的引用，防止内存泄漏。
- 异常处理：考虑如何传递和处理异步操作中的异常。

### 总结

自定义异步等待器是 C# 中强大但较少使用的特性，通过实现`INotifyCompletion`接口，你可以让任何类型支持`await`语法，为异步编程提供极大的灵活性。

### Task

#### 特点

- .NET 标准库的一部分：无需额外依赖，支持`async/await`语法。
- 基于线程池：适用于 I/O 密集型和 CPU 密集型操作，但可能产生线程切换开销。
- 通用性强：可在任何 C# 环境中使用。

#### 在 Unity 中的局限性

- 不支持主线程同步：Unity 的 UI 和组件操作必须在主线程执行，而`Task`默认在线程池线程上运行。
- 内存分配问题：频繁创建`Task`会导致 GC 压力，影响游戏性能。
- 缺少对 Unity 生命周期的支持：如协程、帧同步等

###  UniTask

#### 特点

- 专为 Unity 优化：轻量级、低 GC 分配，支持`async/await`语法。
- 支持主线程同步：通过`UnityMainThreadDispatcher`确保代码在主线程执行。
- 集成 Unity 特性：可直接替代协程（`IEnumerator`），支持`WaitForSeconds`、`WaitUntil`等。
- 高性能：使用值类型（`ValueTask`）和池化技术减少内存分配。

#### 核心优势

- 减少 GC 压力：避免了`Task`的堆分配问题，适合移动游戏。
- 与 Unity 协同工作：无缝集成 Unity 的生命周期和组件系统。
- 丰富的扩展方法：如`ToUniTask()`可将协程转换为`UniTask`。

### ET 框架的 ETTask

#### 特点

- 专为游戏服务器和客户端设计：ET 框架（`Entitas` + `Task`）的核心组件。
- 分布式任务系统：支持跨进程、跨服务器的异步操作。
- 集成 Actor 模型：通过`Entity`和`Component`管理异步任务的生命周期。
- 自定义 `Awaiter`：实现高效的异步等待机制。

#### 核心优势

- 分布式支持：内置 RPC 机制，适合开发分布式游戏服务器。
- 高性能：设计目标是低延迟、高并发，适合 MMO 等大型项目。
- 统一异步模型：客户端和服务器使用相同的异步 API。

| **内存分配**     | 堆分配（每次创建新 Task 对象）    | 零 GC 分配（值类型，栈上分配）     | 基于 Task，少量堆分配（框架优化）   |
| **性能**         | 中等，适合通用场景                | 高（无分配延迟，适合高频调用）     | 中等偏高（优化后接近原生 Task）     |
| **返回类型**     | `Task`/`Task`                     | `UniTask`/`UniTask`                | `ETTask`/`ETTask`                   |
| **生态支持**     | .NET 全平台通用                   | Unity 社区主流（支持 URP/HDRP 等） | ET 框架深度集成（分布式游戏开发）   |
| **核心特性**     | 原生支持 async/await，功能全面    | 支持协程转 Task、低延迟等待        | 内置网络协议、热更新支持            |
| **异常处理**     | 传统 try-catch 捕获               | 兼容 C# 异常机制，支持自定义等待器 | 扩展 Task 异常处理，支持框架级日志  |
| **适用场景**     | 通用后端开发、桌面应用            | Unity 游戏逻辑、高性能渲染管线     | ET 框架项目、分布式系统、热更新游戏 |
| **学习成本**     | 低（.NET 基础必备）               | 中（需学习 UniTask 特化 API）      | 高（依赖 ET 框架整体生态）          |
| **典型代码示例** | `await Task.Delay(1000);`         | `await UniTask.Delay(1000);`       | `await ETTask.Run(() => { ... });`  |
